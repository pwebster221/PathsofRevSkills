# Paths of Reverence — Brand System

**Status:** v1, 2026-05-17
**Owner:** paul.webster@dubtowndesigns.com
**Scope:** The visual and verbal system applied to the *Paths of Reverence* (PoR) Coding Bible and any future PoR-authored documentation, interface, or artifact. This document is the spec; the Coding Bible is the first work that conforms to it.

---

## 1. Principle

The PoR ecosystem already carries a symbolic vocabulary: seven classical planets, Hermetic principles, Tarot, MBTI, Enneagram, the Three-Duality container archetype. The brand does not *decorate* that vocabulary — it *renders* it. Every visual choice traces back to a symbolic anchor that already does load-bearing work elsewhere in the system.

Three rules govern the whole system:

1. **The substrate is parchment, not screen.** Even on screen, the document reads as a working notebook of a hermeticist — restrained, scribed, considered. No gradients, no glass, no glow.
2. **Sigils are operational, not ornamental.** A glyph means something. It tells you what kind of thing you are reading, where it sits in the system, how to handle it.
3. **The operational fact comes first.** Symbolic framing follows. We do not bury infrastructure inside metaphor. Tight register before Deep register, always.

---

## 2. The Planetary Spine

The source Coding Bible is structured as a triad — *Frameworks → Programs → Coding Rules*. Each section is bound to a classical planet that already carries its theme:

| Section | Planet | Role |
|---|---|---|
| Part I — Frameworks | **Mercury ☿** | The conduits. What carries the work. |
| Part II — Programs | **Sol ☉** | The manifest. What the work has become. |
| Part III — Coding Rules | **Saturn ♄** | The boundary. How we hold the work. |

A reader who knows the spine can navigate by glyph alone. The full seven-planet palette extends this vocabulary across the document — *Mars* marks the scoring engine, *Luna* marks memory, *Jupiter* marks frameworks of expansion, *Venus* marks relational work — but the triad is the spine.

## 3. Palette

Two tones per planet — a darker **ink** (safe for text) and a lighter **leaf** (safe for backgrounds, rules, ornaments). Plus a parchment substrate and a single ink-black.

### Planetary tones

| Planet | Glyph | Leaf | Ink | WCAG body? |
|---|---|---|---|---|
| Saturn | ♄ | `#3A3D5E` | `#1A1B2E` | ✓ AAA on Vellum |
| Jupiter | ♃ | `#3A5BAC` | `#1F2C5A` | ✓ AAA on Vellum |
| Mars | ♂ | `#C44343` | `#7A1F20` | ✓ AA on Vellum |
| Sol | ☉ | `#E0BB5C` | `#8A6E2A` | Display & headings only; use ink-tone for body |
| Venus | ♀ | `#7AA88A` | `#3A5C45` | ✓ AA on Vellum |
| Mercury | ☿ | `#D78B58` | `#8A5028` | ✓ AA on Vellum |
| Luna | ☽ | `#E5E2D8` | `#7A7263` | Caption/secondary only |

### Substrate & neutrals

| Role | Hex | Notes |
|---|---|---|
| Vellum (page) | `#F4EFE3` | The default background — a warm, faintly aged off-white. |
| Ink (body text) | `#1A1B2E` | Saturn's deepest tone. The default text color. |
| Faded ink | `#5A5040` | Secondary text, captions, meta. |
| Rule line | `#B8A582` | Hairlines, dividers, table borders. |
| Margin pencil | `#9E927C` | The barely-visible mark — for very-low-emphasis annotations. |

### Contrast rules

- Body type is always Ink `#1A1B2E` on Vellum `#F4EFE3` unless a deliberate planetary register is needed.
- Sol gold `#C8A04A` is **display only** — minimum 18pt, ideally 24pt+. Body Sol uses the ink-tone `#8A6E2A`.
- Luna leaf `#E5E2D8` is too pale for type; reserve it for paper-on-paper effects.
- Every coloured headline must clear WCAG AA against Vellum at its used size. The table above is the authority; deviate only with a measurement.

## 4. Typography

A three-voice system — serif for symbolic register, sans for operational metadata, mono for everything terminal.

### Families

| Role | Family | Fallback stack |
|---|---|---|
| Display (covers, dividers, titles) | **Cormorant Garamond** | `"EB Garamond", "Iowan Old Style", Georgia, serif` |
| Body serif (prose, entries) | **EB Garamond** | `"Iowan Old Style", "Hoefler Text", Georgia, serif` |
| Operational sans (captions, ops meta, sidebar) | **Inter** | `system-ui, -apple-system, "Segoe UI", sans-serif` |
| Monospace (code, paths, ports, memory refs) | **JetBrains Mono** | `"SF Mono", Menlo, Consolas, monospace` |

### Type scale (base 16px / 12pt)

| Token | Size | Family | Weight | Tracking | Use |
|---|---|---|---|---|---|
| `display-xl` | 64px | Cormorant | 500 | -0.5px | Cover title |
| `display-l` | 44px | Cormorant | 500 | -0.25px | Part divider title |
| `display-m` | 32px | Cormorant | 500 | 0 | Section open |
| `h1` | 26px | EB Garamond | 600 | 0 | Entry title |
| `h2` | 20px | EB Garamond | 600 | 0 | Sub-entry |
| `h3` | 16px | EB Garamond | 600 | 0.5px | Field label (sm caps) |
| `body` | 12pt / 16px | EB Garamond | 400 | 0 | Default prose |
| `body-tight` | 10.5pt / 14px | EB Garamond | 400 | 0 | Inside tables, callouts |
| `caption` | 10pt | Inter | 500 | 0.5px | Tier markers, ops meta |
| `code` | 10.5pt | JetBrains Mono | 400 | 0 | Inline `code` and blocks |
| `meta` | 9pt | Inter | 500 | 1px | Field labels in small caps |

### Field labels

The Coding Bible's repeating fields (`Purpose`, `Where used`, `Version/Source`, `Conventions & Gotchas`, `Links`) are rendered in **Inter, 9pt, all-caps, tracking +1px**, in Faded ink `#5A5040`. They sit above the content, not inline. This makes the field labels almost feel like *typesetter's marks* — present but quiet, the way they would be in a working catalog.

## 5. Sigils & Glyphs

The PoR system has three orders of glyph. Use them in this order of preference; reach lower only when the higher order does not apply.

### 5.1 Planetary glyphs — primary

Unicode astrological glyphs render reliably in modern PDFs and browsers. These are the only glyphs that mark *sections* and *registers* of the system.

`☉ Sol  ☽ Luna  ☿ Mercury  ♀ Venus  ♂ Mars  ♃ Jupiter  ♄ Saturn`

A glyph is sized to the heading it accompanies and rendered in the planet's **ink** tone. Headlines should *lead* with the glyph, then the text:

> **☿ Frameworks**
> *The Mercurial register — what carries the work.*

### 5.2 Three-Duality archetype sigils

The container archetypes are already a three-axis classification (Deep/Surface × Persistent/Consumable × Iterative/Static). Render each archetype as a **three-mark sigil** built from a consistent axis vocabulary, so the sigil itself is decodable:

| Axis | Mark (left state) | Mark (right state) |
|---|---|---|
| Depth | ◆ Deep | ◇ Surface |
| Permanence | ● Persistent | ○ Consumable |
| Velocity | ▲ Iterative | ▼ Static |

This yields:

| Archetype | Sigil | Common name |
|---|---|---|
| DPS | ◆●▼ | Vault |
| DPI | ◆●▲ | Sanctum |
| DCI | ◆○▲ | Laboratory |
| DCS | ◆○▼ | Bunker |
| SPI | ◇●▲ | Forum |
| SPS | ◇●▼ | Monument |
| SCI | ◇○▲ | Workshop |
| SCS | ◇○▼ | Billboard |

A reader who knows the axes can read any sigil cold. A reader who doesn't can look it up in the appendix and never again need to — the marks are mnemonic.

Sigils are rendered in Saturn ink `#1A1B2E`, letter-spaced `+2px`, and may appear next to a container name anywhere in the document:

> *CT 595 — monitoring* ◆●▲ — Grafana + Prometheus, its own tunnel.

### 5.3 Callout marks

A small mark family for in-body callouts. Each mark sits in the left margin of the callout block, the planetary tone tinting the rule line.

| Mark | Name | Use | Tone |
|---|---|---|---|
| ▲ | **Gotcha** | "Conventions & Gotchas" — the load-bearing trapdoors. | Mars `#7A1F20` |
| ✦ | **Pattern** | A successful pattern worth remembering. | Sol `#8A6E2A` |
| ◐ | **Drift** | Wrapper / client drift warning. | Mercury `#8A5028` |
| ⧈ | **Memory** | A `[[memory-name]]` cross-reference. | Luna `#7A7263` |
| ✱ | **Decision** | A decided-but-not-yet-deployed pattern. | Jupiter `#1F2C5A` |
| † | **Read-only** | Hands off. CT 2001, production graphs. | Saturn `#1A1B2E` |

Marks may compound — a Gotcha that is also a Drift gets both marks.

### 5.4 Hermetic principle marks (reserved)

The seven Hermetic principles (Mentalism, Correspondence, Vibration, Polarity, Rhythm, Cause/Effect, Gender) are *reserved* for future use as section tags inside the Coding Rules part, once that section grows to its full size in the `rules/*.md` future docs. They are not used in v1.

## 6. Voice & Tone — the Esoteric Diction tiers

The source `[[project_esoteric_diction]]` already names three tiers. The brand system formalizes them and assigns each a *register glyph* so a reader can see which tier they are in at a glance.

### Tier I — **Tight** ⟜

Operational. Verb-first. No hedges, no metaphor, no warmup. The register of runbooks, MCP responses, and ops chatter.

> Force `protocol: http2`. QUIC default thrashes. Batch ingress changes — reload is a restart.

**When to use:** error messages, runbook steps, MCP tool outputs, terminal echo, any line where the reader is mid-task.

### Tier II — **Standard** ⟝

The working register. Plain English with one foot in the symbolic vocabulary. Most of the Coding Bible's prose lives here.

> The Cloudflare Tunnel will drop intermittently if it defaults to QUIC. Pin to HTTP/2 in `config.yml` and the 502s stop. Note that `systemctl reload cloudflared` is a restart, not a reload — batch ingress edits to amortize the ~7s outage.

**When to use:** documentation prose, entry bodies, explanatory passages, README files.

### Tier III — **Deep** ⟞

Symbolic synthesis. For teaching, onboarding, scaffolding *why*. Used sparingly — at section openings, in the "How to read this Bible" page, for the conceptual core of a pattern.

> The tunnel is a vein in the body of the host. QUIC, by its nature, treats the path as ephemeral — apt for the messenger but not for the work. We pin to HTTP/2 because the work asks for a path that holds across the reload, and the reload, here, is a small breaking of the world.

**When to use:** onboarding pages, the opening epigraph of each Part, conceptual essays, the colophon. *Never* default to Deep — Tight is the operational register and Standard is the working register; Deep is invitational.

### Register glyphs

Each entry, in the contributor-facing kit, may carry a tier glyph in its head — `⟜` Tight, `⟝` Standard, `⟞` Deep — set in Inter 9pt, Faded ink. The Coding Bible itself is mixed: entry bodies are Standard, Conventions & Gotchas are Tight, Part openings are Deep.

## 7. Section Iconography Rules

A normative checklist for laying out any PoR-style document.

1. **Every Part opens with a divider page.** Large planetary glyph (display-l), the part name, a short epigraph in Deep register, a thin Sol-leaf rule line.
2. **Every entry leads with its planetary mark when relevant.** A FastMCP entry may carry ☿ Mercury. An entry about Mars Scoring carries ♂. Default to no mark if no planet applies — a mark *means something* and should not appear at random.
3. **Field labels are typesetter's marks.** Small caps, Inter 9pt, Faded ink. They float above their content, not inline with it.
4. **Conventions & Gotchas is visually distinct.** A left rule line in Mars ink, a ▲ mark in the margin, body-tight prose. This is the load-bearing register — make it look like it knows.
5. **`[[memory-name]]` is monospace.** Always. With a leading ⧈ Memory mark on first reference per section.
6. **Paths and ports are monospace.** `CT 520:8060`, `/root/CLAUDE.md`, `mcp__claude_ai_repository__*`. Never paraphrased into prose.
7. **External URLs are italic serif.** They are not infrastructure; they are references.
8. **Tables get hairline rules in Rule-line `#B8A582`, never solid borders.** Tables are reference furniture; they should feel like a published index, not a spreadsheet.

## 8. Do / Don't

### Do

- Lead with the operational fact; symbolic framing follows.
- Treat **Conventions & Gotchas** as load-bearing. The bare lines are the work.
- Preserve `[[memory-name]]` anchors verbatim — they are live references into Paul's memory system, not decorative citations.
- Carry the appendix cross-reference tables forward intact. They are the index of the system.
- Cite the planetary spine when introducing a new Part. The reader should know which register they have entered.
- Render Three-Duality archetypes with their decoded sigil at least once per entry, then the common name afterward.

### Don't

- ❌ Sol gold for body type. It fails AA below 18pt. Use the Sol ink-tone `#8A6E2A` for any Sol-tinted body text.
- ❌ Emoji as decoration. The only sanctioned glyphs are planetary, alchemical, the duality marks, and the callout family. No 🚀, no 🎨, no 🔥.
- ❌ Rewriting technical substance "to make it flow." The substance is fixed. Visual flow is achieved by typography and rhythm, not paraphrase.
- ❌ Softening **Conventions & Gotchas** into "Notes," "Tips," or "FYI." The name carries the weight. Keep it.
- ❌ Defaulting to Deep register. Tight is operational; Standard is the working register; Deep is the invitation. Use Deep less than you think you should.
- ❌ Generic startup palette ("primary blue, secondary green, neutral grey"). Every color in this system has a name and a referent in the symbolic vocabulary.

## 9. Cross-link conventions

The Coding Bible is part of a larger memory graph. The brand system codifies how that graph is rendered in prose.

| Reference type | Render | Example |
|---|---|---|
| Memory anchor | ⧈ + monospace, in Luna ink the first time per section | ⧈ `[[feedback_fastmcp_tunnel_setup]]` |
| Path in repo | monospace | `/root/CLAUDE.md` |
| Container / port | monospace | `CT 520:8060` |
| Hostname | monospace italic | *`raw-charts.dubtown-server.us`* |
| External URL | italic serif | *https://docs.anthropic.com/claude/...* |
| Linear issue | monospace, prefixed `PAT-` | `PAT-509` |
| MCP tool | monospace | `mcp__claude_ai_repository__*` |
| Authoritative neighbor doc | monospace + small-caps label `SOT:` | SOT: `/root/CLAUDE.md` |

The `SOT:` ("source of truth") label is reserved for the two authoritative neighbor docs named in the Coding Bible's preamble — `/root/CLAUDE.md` and `/root/.claude/projects/-root/memory/MEMORY.md` — so a reader who hits a fact in the Bible can always trace to ground.

## 10. Layout grid (PDF & site)

A simple 12-column grid on letter (8.5×11in) for the PDF and a single-column 720px content width on the site. Generous margins — the page should feel like a scribed page, not a packed one.

| Setting | PDF | Site |
|---|---|---|
| Page | 8.5 × 11in | n/a |
| Outer margin | 1.0in | 24px gutter |
| Inner margin | 1.0in | — |
| Top / bottom | 0.9in | 48px / 48px |
| Body measure | ~64 characters | ~72 characters |
| Line height | 1.45 | 1.55 |
| Paragraph indent | none (block paragraphs, 0.6em gap) | same |

Page furniture: a thin Rule-line hairline runs the full text width above the running header. Running header carries the Part name in small caps, Faded ink. Running footer carries the page number in Inter 9pt, centered.

## 11. Concrete examples

### A well-formed entry

> ### ☿ FastMCP
>
> ⟜ Tight register on the gotcha; Standard register on the body.
>
> **PURPOSE** &nbsp; Pythonic decorator-based MCP server framework.
> **WHERE USED** &nbsp; Every MCP service in this fleet.
> **VERSION / SOURCE** &nbsp; pip.
>
> ▲ **CONVENTIONS & GOTCHAS**
> For tunnel deployment, `mcp.run()` breaks browser/strict clients. Pattern: custom `main()` that runs uvicorn with `proxy_headers=True` and `forwarded_allow_ips="*"`, plus Starlette `CORSMiddleware` mounted before the MCP app.
>
> ⧈ **LINKS** &nbsp; `[[feedback_fastmcp_tunnel_setup]]`, `[[feedback_fastmcp_mounted_path]]`.

### A well-formed Part opener

> # ☿ Part I — Frameworks
>
> *The Mercurial register: what carries the work.*
>
> Frameworks are not the work. They are the medium through which the work moves — Mercury's office. The catalog that follows is selective by design. Each framework here is load-bearing on at least one production service; each carries at least one Gotcha that has cost time. Read the **Conventions & Gotchas** lines first if you are short on time.

### A well-formed callout

> ▲ **GOTCHA — `cloudflared` has no graceful reload**
> `systemctl reload cloudflared` actually restarts (~7s outage). Batch ingress changes.
> ⧈ `[[feedback_cloudflared_no_exec_reload]]`

## 12. Versioning

This brand system is **v1**. Changes that affect rendered output (palette, type scale, sigil set, tier glyphs) bump the minor version and require a rebuild of the Coding Bible PDF. Changes that affect only voice & tone guidance bump the patch version.

The colophon page of every PoR document records the brand system version it was built against.
