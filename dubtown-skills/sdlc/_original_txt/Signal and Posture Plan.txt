## What goes in `references/`

That subfolder should hold the source material that backs the skill's claims - not the whole methodology doc, just anchors for attribution and retrieval:

```
sdlc-tdd/
├── SKILL.md
└── references/
    └── SOURCES.md      ← key citations: authors, books, URLs, doc numbers
```

Keep `SOURCES.md` lightweight. One block per source, enough for an agent or human to trace the lineage without loading a full bibliography system.

## The two optional but high-value additions

**`SKILL-TEMPLATE.md`** at root - a blank version of the YAML frontmatter + section structure every skill follows. When you or an agent authors a new skill, it starts here. Enforces consistency without a build tool.

**`README.md`** at root - one page that explains: what this repo is, how the two tiers relate, how an agent is expected to use the MANIFEST, and how a human adds a new skill. This is the "cold start" document for any new agent or collaborator hitting the repo fresh.
